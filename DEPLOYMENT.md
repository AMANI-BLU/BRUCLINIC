# Deploying BruClinic

BruClinic is split into two deployables:

```
Vercel (static React SPA)  ──HTTPS──►  Render Web Service (Node API)  ──private──►  Render PostgreSQL
   frontend/                              backend/                                 bruclinic-db
```

- **Frontend:** Vercel, built from `frontend/` with Vite.
- **Backend:** Render Web Service, built from `backend/`.
- **Database:** Render PostgreSQL, connected to the API over Render's private network.

The repository already contains [`render.yaml`](../render.yaml) and [`frontend/vercel.json`](../frontend/vercel.json), so most settings are handled for you.

---

## 1. Before you deploy

1. Push the project to GitHub (the configured remote is `AMANI-BLU/BRUCLINIC`, branch `master`).
2. Create accounts on [Render](https://render.com) and [Vercel](https://vercel.com).
3. Decide on two names up front:
   - Render service name, for example `bruclinic-api` → API URL `https://bruclinic-api.onrender.com`
   - Vercel project name, for example `bruclinic` → frontend URL `https://bruclinic.vercel.app`

> **Real clinic data warning:** Render's Free PostgreSQL expires **30 days** after creation. After a 14-day grace period it is deleted, including all data. Use a paid Render Postgres plan (or another managed PostgreSQL provider) for anything beyond a demo. Free web services also sleep after 15 minutes of inactivity and take about a minute to wake up.

## 2. Deploy the backend on Render

You can use the Blueprint (recommended) or create the services manually.

### Option A — Blueprint (recommended)

1. In the Render Dashboard, click **New → Blueprint**.
2. Connect the GitHub repository and select the `master` branch.
3. Render reads `render.yaml` and shows:
   - `bruclinic-db` — PostgreSQL database
   - `bruclinic-api` — Node web service
4. It will prompt for the variables marked `sync: false`:
   - `CORS_ORIGIN` — the Vercel URL. If you do not know it yet, enter a placeholder such as `https://placeholder.vercel.app` and update it in step 4.
   - `SEED_ADMIN_USERNAME`, `SEED_ADMIN_PASSWORD`, `SEED_ADMIN_EMAIL` — the first administrator account.
5. Click **Apply**. Render creates the database, deploys the API, runs migrations, and then runs the one-time `db:seed` hook.
6. Wait for the deploy to finish and copy the service URL, for example:
   `https://bruclinic-api.onrender.com`

The Blueprint sets these important values for you:

| Setting | Value |
|---|---|
| Root directory | `backend` |
| Build command | `npm ci` |
| Start command | `npm run db:migrate && npm start` |
| Health check | `/api/health` |
| Database connection | `DATABASE_URL` from `bruclinic-db` |
| JWT secret | generated by Render |
| Bind address | `HOST=0.0.0.0`, `PORT` supplied by Render |

### Option B — Manual setup

1. **Create the database**
   - **New → PostgreSQL**
   - Name: `bruclinic-db`
   - Region: **Frankfurt** (closest to Ethiopia; keep the API in the same region)
   - Plan: Free for a demo, paid for real data
   - After creation, open **Connect** and copy the **Internal Database URL**.

2. **Create the web service**
   - **New → Web Service** → connect the repository.
   - Name: `bruclinic-api`
   - Region: **Frankfurt** (must match the database region)
   - Root Directory: `backend`
   - Runtime: **Node**
   - Build Command: `npm ci`
   - Start Command: `npm run db:migrate && npm start`
   - Health Check Path: `/api/health`

3. **Add environment variables**

   | Key | Value |
   |---|---|
   | `NODE_ENV` | `production` |
   | `HOST` | `0.0.0.0` |
   | `DATABASE_URL` | Internal Database URL from step 1 |
   | `JWT_SECRET` | A random value — use Render's **Generate** button, or run the command below |
   | `CORS_ORIGIN` | Your Vercel URL (placeholder is fine initially) |
   | `SEED_ADMIN_USERNAME` | e.g. `admin` |
   | `SEED_ADMIN_PASSWORD` | At least 10 characters, with an uppercase letter and a number |
   | `SEED_ADMIN_EMAIL` | e.g. `admin@borana.edu.et` |
   | `SEED_ADMIN_NAME` | e.g. `Clinic Administrator` |

   Generate a JWT secret locally if you prefer:

   ```powershell
   node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
   ```

4. **Run the first migration and seed**

   Free Render services do not have a pre-deploy command or shell access. Choose one of these:

   **4a. One-time start command (easiest if you already clicked Deploy):**
   - Set the Start Command to:
     `npm run db:migrate && npm run db:seed && npm start`
   - Deploy once. Confirm you can log in.
   - Change the Start Command back to:
     `npm run db:migrate && npm start`
   - Deploy again.

   **4b. From your laptop against the external database URL (also works on free):**
   - Open the database's **Connect** menu and copy the **External Database URL**. It should end with `?sslmode=require`.
   - Run from the project root:

   ```powershell
   cd backend
   $env:DATABASE_URL = "postgresql://USER:PASSWORD@EXTERNAL-HOST:5432/bruclinic?sslmode=require"
   $env:SEED_ADMIN_USERNAME = "admin"
   $env:SEED_ADMIN_PASSWORD = "ChangeMe12345"
   $env:SEED_ADMIN_EMAIL = "admin@borana.edu.et"

   npm ci
   npm run db:migrate
   npm run db:seed

   Remove-Item Env:DATABASE_URL, Env:SEED_ADMIN_USERNAME, Env:SEED_ADMIN_PASSWORD, Env:SEED_ADMIN_EMAIL
   ```

   The API's `DATABASE_URL` must remain the **internal** URL so Render traffic stays on the private network.

5. **Deploy** and open:
   `https://bruclinic-api.onrender.com/api/health`

   A healthy response looks like:

   ```json
   {
     "status": "healthy",
     "database": { "connected": true, "setupRequired": false }
   }
   ```

   `503` means the API cannot reach the database. Check `DATABASE_URL` and that the service and database are in the same region.

### If you upgrade the Render service to a paid plan

Move migrations out of the start command:

- **Pre-Deploy Command:** `npm run db:migrate`
- **Start Command:** `npm start`

Paid services also get shell access, pre-deploy commands, and backups (paid databases).

## 3. Deploy the frontend on Vercel

1. In Vercel, click **Add New → Project** and import the same repository.
2. Set **Root Directory** to `frontend`.
3. Framework Preset should be **Vite**. The included `frontend/vercel.json` sets:
   - Build Command: `npm run build`
   - Output Directory: `dist`
   - SPA rewrite: every unknown path serves `index.html`
4. Add an environment variable:

   | Key | Value | Environments |
   |---|---|---|
   | `VITE_API_URL` | `https://bruclinic-api.onrender.com/api` | Production and Preview |

   Use your actual Render service URL. Keep the `/api` suffix. No trailing slash is required (the client removes one if present).
5. Click **Deploy**.
6. Copy the production URL, for example `https://bruclinic.vercel.app`.

> `VITE_API_URL` is compiled into the JavaScript at build time. If you change it, you must create a new Vercel deployment — restarting is not enough.

The `frontend/vercel.json` rewrite is what makes deep links work. Without it, refreshing a page such as `/dashboard` would return a Vercel 404.

## 4. Connect the two: CORS

The API only accepts browser requests from origins listed in `CORS_ORIGIN`.

1. Go to **Render → bruclinic-api → Environment**.
2. Set:

   ```text
   CORS_ORIGIN=https://bruclinic.vercel.app
   ```

3. Save. Render restarts the service.

Notes:

- Use the exact scheme and host, with **no trailing slash**.
- Multiple origins are comma-separated:
  `https://bruclinic.vercel.app,https://clinic.borana.edu.et`
- Vercel **preview** deployments have unique URLs. Either add the specific preview URL temporarily to `CORS_ORIGIN`, or test previews by pointing `VITE_API_URL` at a separate backend.
- If you later add a custom domain to Vercel, add it to `CORS_ORIGIN` too.

---

## 5. Verify the deployment

1. **Health:** `https://bruclinic-api.onrender.com/api/health` returns `200` and `"status": "healthy"`.
2. **Login:** open the Vercel URL and sign in with the seeded administrator.
3. **Deep link:** navigate to a page, then refresh the browser. It should still render, not show a 404.
4. **Browser console:** no CORS or mixed-content errors.
5. **Database:** open **Admin → Backup & Restore** and export a backup once everything works.

---

## 6. Deploying updates later

- Push to `master`.
- Render rebuilds and restarts the API; migrations run automatically with the current start command.
- Vercel rebuilds the frontend automatically.
- If you changed an environment variable in Vercel, trigger a new deployment.
- If you changed `CORS_ORIGIN` or any Render variable, saving it restarts the API.

## 7. Free-tier limitations and production advice

Render Free is fine for a demo, not for a live clinic:

| Limitation | Impact |
|---|---|
| Free PostgreSQL expires after 30 days (14-day grace) | Data is deleted unless you upgrade |
| Only one Free PostgreSQL database per workspace | A second Blueprint/database will be rejected |
| 1 GB database storage | Limited headroom |
| No managed backups on free databases | Export backups manually |
| Free web service sleeps after 15 minutes | First request after idle takes about a minute |
| 750 free instance hours per month | Enough for one always-on service, little else |
| No shell access or pre-deploy commands | Migrations must run on start or from your laptop |
| 512 MB RAM / 0.1 CPU | Fine for a small clinic, tight under load |

For production:

- Upgrade the Render PostgreSQL plan (paid plans start at $6/month) and the web service (from $7/month).
- Move migrations to the Pre-Deploy Command and keep `npm start` as the start command.
- Enable Render's database backups.
- Consider restricting database external access to your office/VPN IP range after initial setup.
- Rotate `JWT_SECRET` if it is ever exposed; this signs everyone out.
- After the first successful seed, clear `SEED_ADMIN_PASSWORD` from Render's environment if you do not need to run `db:seed` again.

## 8. Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| Deploy fails at `npm ci` | `backend/package-lock.json` missing or out of sync | Run `npm install` in `backend/`, commit the lockfile |
| Build succeeds, health check fails | API cannot reach the database | Use the **internal** `DATABASE_URL`; confirm same region |
| `status: "unhealthy"`, `database.connected: false` | Wrong `DATABASE_URL`, database still provisioning, or SSL issue | Check the URL, wait for the DB, use `?sslmode=require` only for external URLs |
| Login page says network error | Wrong `VITE_API_URL`, API asleep, or CORS | Check the browser Network/Console tabs; wake the API; verify `CORS_ORIGIN` |
| `Access-Control-Allow-Origin` error | Origin mismatch | Exact Vercel URL, no trailing slash; save and let Render restart |
| Refreshing a page returns 404 | SPA rewrite missing | Confirm `frontend/vercel.json` is deployed and Root Directory is `frontend` |
| `Server startup aborted due to environment configuration issues` | `JWT_SECRET` missing or placeholder | Set a random secret of at least 32 characters |
| `Cannot reach the database server (localhost:5432)` | `HOST`/`DATABASE_URL` not set on Render | Set `HOST=0.0.0.0` and `DATABASE_URL` |
| Deep links work locally but not on Vercel | `vercel.json` not at the project root | It must be in `frontend/` when Root Directory is `frontend` |
| Admin cannot log in after redeploy | Seed variables changed but `db:seed` was not re-run | Run `db:seed` once with the desired `SEED_ADMIN_*` values |
| First request takes ~1 minute | Free service spun down | Expected on Free; upgrade or ping it periodically |

- [ ] Admin seeded and login tested
